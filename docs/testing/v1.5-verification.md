* Preview the actual deletion target in the highlighted list and details panel; preserve stored bytes until confirmation.

* Reject corrupt JSON, a null root, missing/null student arrays, null student entries, and missing required fields;
  display the protective startup alert, open no roster, and preserve each original file byte-for-byte.

## Release integrity

The v1.4 release contained only two JARs and a stale manifest. Both published JARs were downloaded; their actual
SHA-256 values were used to regenerate `SHA256SUMS.txt`, removing references to absent screenshot assets. The JARs
were not replaced. The corrected manifest was downloaded again and verified against both original binaries.

For v1.5, follow the [release procedure](../DevOps.md#making-a-release): build both architectures from the final
tagged source, generate checksums last, download the published assets, verify hashes, and run the published JAR.
The release tracker records the outcome so this source document does not prematurely claim a future publication.
